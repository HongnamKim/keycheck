# 이미지 축소본·틀 글 미리 읽기·수집 기간 설계

작성 2026-11-04. 기존 설계(`2026-11-01-keycheck-design.md`) 4.5의 "이미지 저장 방식은 배포 단계에서 다시 정한다"를 이 문서로 정한다.

## 1. 왜 하는가

- **Vercel 이미지 변환 한도:** 지금은 `next/image`가 원본을 받아 줄인다. Vercel Hobby는 이미지 변환이 월 5,000건이고, "서로 다른 이미지 × 크기"마다 처음 한 번(그리고 캐시가 빠진 뒤 다시) 1건으로 센다. 원문 이미지가 이미 1,747장이고 글당 평균 15장이라, 크롤러가 상세를 한 번 훑기만 해도 한도에 닿는다. 프론트는 Vercel에 배포하기로 했다(배포 결정).
- **첫 방문자 속도:** Vercel이 줄이는 방식은 캐시에 없을 때 방문자가 원본 호스트(postimg 3~9초, 15MB짜리 geekhack 첨부 7.8초)를 그대로 기다린다. 새 글이 가장 많이 보이는 서비스라 캐시 미스가 잦다.
- **목록에서 이미지가 안 보임:** 과거 글 확보로 생긴 틀 글은 상세를 열기 전까지 이미지가 없어 목록·하단 목록에 "열면 불러와요"만 보인다. geekhack 목록에서 이미지를 볼 수 없어 일일이 들어가 봐야 한다는 점이 사용자가 가장 아쉬워한 점이고, 지금 목록이 그걸 답습하고 있다.
- **너무 오래된 글:** 2019년 IC처럼 오래된 글은 볼 필요가 없다. 기간을 두면 geekhack 요청·요약 요금·저장 용량이 함께 준다.

## 2. 목표와 비목표

**목표**
- 화면의 모든 이미지가 Vercel 이미지 변환을 거치지 않는다(변환 0건).
- 목록 카드, 상세 하단 목록, 상세 갤러리는 우리가 미리 만든 축소본을 브라우저가 저장소에서 직접 받는다.
- 틀 글은 사용자가 열지 않아도 백엔드가 미리 원문을 읽어, 목록에서도 곧 이미지가 보인다.
- 2020-01-01 이후 작성된 글만 모으고 보여준다.

**비목표**
- 확대 보기(라이트박스)용 큰 축소본. 확대 보기는 원본을 그대로 보여준다(느릴 수 있음을 받아들임).
- 원본 보관. 원본은 계속 원래 호스트에 두고 주소만 저장한다.
- 축소본 지우기·정리(글 숨김, 이미지 교체 시). 지금은 이미지가 한 번 쓰이고 바뀌지 않는다.
- 크기가 여러 개인 축소본(반응형 srcset). 이미지마다 640px 하나, 대표 이미지만 1280px를 하나 더 만든다(3.1).
- 위키식 대표 이미지 교체(나중 기능). 다만 이번 설계가 그 길을 막지 않아야 한다.

**하면 안 되는 것 (기능은 돌아가도 실패로 본다)**
- geekhack 요청 간격(2초) 제한을 우회하는 것. geekhack 첨부 이미지 받기도 이 제한을 거친다.
- 미리 읽기·축소본 작업이 사용자 요청(상세 열기, 목록 확보)을 늦추는 것. 둘 다 가장 낮은 우선순위다.
- 자동 테스트가 실제 geekhack, 실제 이미지 호스트, 실제 R2를 호출하는 것.
- 화면 문구에 "해외"를 쓰는 것.

## 3. 정한 것

### 3.1 축소본 (사용자 결정)

- 형식은 **WebP**. 백엔드가 원본을 받아 줄이고 인코딩한다. Java 기본 ImageIO는 WebP를 쓰지 못하므로 libwebp를 담은 라이브러리를 추가한다. 맥(로컬)과 리눅스 Docker(배포)에서 모두 돌아야 하며, 안 되면 JPEG로 바꾸고 사용자에게 알린다.
- 크기는 **가로 최대 640px 하나**(원본이 더 작으면 키우지 않음, 비율 유지). 카드(표시 약 320px), 하단 목록(208px), 갤러리 칸(240px)을 고해상도 화면에서도 덮는다.
  - 처음에는 갤러리를 480px로 따로 두려 했으나, R2 무료 용량(10GB)이면 한 크기로 충분해 한 크기로 정했다(Claude 판단).
- **대표 이미지만 가로 최대 1280px를 하나 더** 만든다(사용자 결정). 상세 맨 위 큰 이미지(PC 표시 약 600px, 모바일 화면 폭)가 고해상도 화면에서도 선명하게 보이게 하기 위해서다. 원본이 더 작으면 키우지 않는다. 대표 이미지는 글당 한 장이라 늘어나는 용량은 1GB 미만이다. 카드와 하단 목록은 640px를 쓴다.
- 대상은 **상세 갤러리에 보이는 이미지 전부**(`post_image` 중 `excluded_reason`이 null인 것, 대표 이미지 포함). 제외된 이미지(이모티콘, 배너 등)는 만들지 않는다.
- 저장소는 **Cloudflare R2**(사용자 결정). S3 호환 API로 다룬다. 로컬 개발도 처음부터 **실제 R2 버킷**에 연결하고(사용자 결정), 배포 전에 버킷의 테스트 데이터를 지운다. 로컬용 MinIO는 두지 않는다. 로컬은 공개 주소로 버킷의 r2.dev 주소를 쓰고, 배포 때 연결한 도메인으로 설정만 바꾼다.
- 저장소 객체는 공개 읽기. 브라우저가 공개 주소로 직접 받는다. 배포에서는 Cloudflare에 연결한 도메인(예: `img.<도메인>`)을 쓴다. `r2.dev` 주소는 개발용이라 쓰지 않는다. 배포 세팅은 이 작업 범위가 아니다(배포 때 연결).
- 객체 이름은 다시 만들어도 같은 이름이 되게 이미지 기준으로 정한다(예: `thumbs/<post_image.id>.webp`, 대표 이미지 큰 축소본은 `thumbs/<post_image.id>-1280.webp`). 한 번 올린 객체는 바뀌지 않으므로 길게 캐시한다(`Cache-Control: public, max-age=31536000, immutable`).

**용량 추정:** 2020-01-01 이후 글을 전부 확보해도 약 4,800개 × 15장 × 약 50KB ≈ 3~4GB, 대표 이미지 1280px까지 더해 약 4~5GB. 실제로는 사용자가 스크롤해 확보한 만큼만 생겨 더 적다. R2 무료 10GB 안이고, 넘으면 GB당 월 0.015달러로 막히지 않는다.

### 3.2 축소본 만들기 작업

- 수집과 따로 도는 **백그라운드 작업**(요약 작업 `SummaryWorker`와 같은 방식). 몇 초마다 축소본이 아직 없는 이미지 하나를 처리한다.
- 순서: 최근 글 먼저(본문을 늦게 채운 글 먼저, 같으면 글 번호 큰 글), 글 안에서는 대표 이미지 먼저, 그다음 본문 순서.
- 대표 이미지는 640px와 1280px를 같은 처리에서 함께 만들고, 둘 다 올라가야 완료로 본다.
- 이미지마다 상태를 둔다: 아직 없음 / 완료(공개 주소 또는 객체 이름) / 실패. 실패는 몇 번(예: 3번) 다시 시도한 뒤 멈춘다. 실패한 이미지는 화면이 원본을 직접 보여준다.
- 이미 DB에 있는 이미지(약 1,747장)도 같은 작업이 차례로 처리한다. 따로 일괄 작업을 만들지 않는다.
- **원본 받기 규칙**
  - geekhack 첨부(`ImageSource.ATTACHMENT` 또는 geekhack 호스트)는 기존 `RequestGate`를 거친다. 기다리지 않는 `tryAcquire()`로, 비어 있는 간격만 쓴다(사용자 요청·정기 수집이 우선).
  - 다른 호스트도 너무 몰아서 받지 않게 작업 자체가 한 번에 한 장, 몇 초 간격으로만 돈다.
  - 크기·시간 상한을 둔다(예: 내려받기 25MB, 응답 시간 제한). 아주 큰 이미지는 읽을 때 줄여 읽어(서브샘플링) 메모리를 지킨다.
  - 움직이는 GIF는 첫 장면으로 만든다. 투명 PNG는 WebP가 투명을 지원하므로 그대로 둔다.
- 축소본 작업과 저장소 연결은 설정으로 끌 수 있다. 저장소 설정이 없으면 작업이 돌지 않고, 화면은 원본을 직접 보여준다.

### 3.3 틀 글 미리 읽기 (사용자 결정)

- 백그라운드 작업이 틀 글(본문을 아직 읽지 않은 글) 하나씩을 기존 `fillSkeleton`과 같은 방식으로 채운다. 채워지면 이미지가 저장되고, 축소본 작업과 요약 작업이 이어서 처리한다.
- 순서: 글 번호 큰 글(최근 글)부터. 숨긴 글과 수집 기간 밖 글은 하지 않는다.
- 우선순위가 가장 낮다. `RequestGate.tryAcquire()`(기다리지 않음)로 빈 간격만 쓰고, 실행 간격도 넉넉히(예: 10초에 한 건) 둔다. 사용자가 그 틀 글을 먼저 열면 상세 열기가 채운다(이미 있는 비관적 잠금으로 중복이 없다).
- 비용: 채운 글은 요약되므로 글당 약 1.1센트(Sonnet). 지금 틀 글 245개면 약 2.7달러가 한 번 든다. 사용자가 받아들였다.
- 읽기에 실패한 틀 글을 계속 다시 시도하지 않도록 실패 기록(횟수 또는 마지막 시도 시각)을 둔다.

### 3.4 수집 기간 (사용자 결정: 2020-01-01)

- 기준은 "작성일이 2020-01-01 이후"다. geekhack 목록에는 작성일이 없으므로, 판단은 **글 번호 경계**로 한다. geekhack 글 번호는 게시판과 상관없이 시간순으로 커지기 때문이다.
- 경계 글 번호는 설정값 하나로 둔다(예: `keycheck.collect.since-topic-id`). 값은 DB에 있는 작성일 기준점(정확한 작성일이 있는 글)으로 추정해 정하고, 며칠 오차는 괜찮다. 설정 옆 주석에 "2020-01-01 무렵 첫 글 번호"라고 적는다.
- 적용 위치
  - 정기 수집: 경계보다 작은 글은 저장하지 않는다(오래된 글에 새 댓글이 달려 최근 댓글순 목록에 올라와도). 이미 저장된 그런 글도 목록·하단 목록·상세에서 보이지 않게 한다(숨김 또는 조회 조건, 방법은 구현에 맡김).
  - 과거 글 확보: 받은 쪽의 글이 경계에 닿으면(쪽의 가장 작은 글 번호가 경계보다 작으면) 그 게시판을 끝(`exhausted`)으로 둔다. 경계보다 작은 글은 틀 글로도 저장하지 않는다.
  - 목록·하단 목록 API: 경계보다 작은 글은 나오지 않는다. 무한 스크롤은 경계에서 "끝"이 된다.
  - 미리 읽기·축소본 작업: 경계보다 작은 글은 하지 않는다.

### 3.5 API와 화면

- 목록 카드(`PostCardResponse`)에 대표 이미지 축소본 주소를 더한다(없으면 null). 원본 주소는 그대로 둔다.
- 상세(`PostDetailResponse`)는 갤러리 이미지마다 원본 주소와 축소본 주소(없으면 null)를 함께 준다. 대표 이미지는 640px 축소본과 1280px 큰 축소본 주소를 준다(상세 맨 위는 큰 축소본을 쓴다). 기존 필드를 바꿀지, 새 필드를 더할지는 구현에 맡기되 프론트 타입과 맞춘다.
- 프론트
  - 축소본이 있으면 그 주소를, 없으면 원본 주소를 **브라우저가 직접** 읽는다. 어디서도 Vercel 이미지 변환을 쓰지 않는다(`next/image`를 `unoptimized`로 쓰거나 `<img>`로 바꾼다. 방법은 구현에 맡김).
  - 확대 보기는 원본을 직접 보여준다.
  - 지연 로딩(처음 보이지 않는 카드), 카드 비율(16:10), 지금의 "이미지 없음"·"열면 불러와요" 표시는 유지한다.
  - `next.config.ts`의 `images.remotePatterns` 등 이미지 최적화용 설정은 필요 없어지면 정리한다.

### 3.6 설정과 보안

- 저장소 접속 정보는 환경변수로 받는다: `R2_ENDPOINT`(`https://<계정ID>.r2.cloudflarestorage.com`), `R2_BUCKET`, `R2_ACCESS_KEY_ID`, `R2_SECRET_ACCESS_KEY`, `R2_PUBLIC_URL`(로컬은 r2.dev 주소). 로컬은 `backend/.env`(사용자가 직접 넣음), 배포는 서버 환경변수. 키는 커밋하지 않고 채팅에도 붙이지 않는다. README 환경변수 표와 `.env.example`에 항목을 더한다.
- 접속 정보가 비어 있으면 축소본 작업은 켜지지 않고, 화면은 원본 주소를 쓴다(키 없이도 로컬 실행·테스트가 된다).
- **배포 전 정리:** 버킷의 `thumbs/` 객체를 모두 지운다. 로컬 DB를 배포 DB로 옮기지 않는 한, 배포 DB의 축소본 상태는 처음부터 "없음"이라 다시 만들어진다. 배포 뒤 로컬 개발을 이어갈 때는 같은 버킷에 쓰지 않도록 개발용 버킷을 따로 둔다(같은 이미지 번호가 서로를 덮어쓰기 때문).

### 3.7 검토 후 Claude가 정한 것

- **요청 간격의 우선순위:** 지금 `RequestGate`에는 우선순위가 없어서, 백그라운드 작업이 `tryAcquire()`로 간격을 잡으면 바로 뒤에 온 사용자 요청이 최대 2초 더 기다린다. 그래서 게이트에 백그라운드용 획득을 따로 둔다. 기다리는 사용자·정기 수집 요청이 없고, 마지막 요청 뒤로 간격보다 넉넉한 시간(예: 간격의 2배)이 비었을 때만 잡는다. 그래도 백그라운드가 막 잡은 순간 들어온 사용자 요청은 한 간격(2초)까지 기다릴 수 있고, 이 정도는 받아들인다.
- **열린 목록의 자동 갱신:** 미리 읽기나 축소본이 끝나도 이미 열려 있는 목록은 스스로 바뀌지 않는다. 다음에 목록을 열 때 반영된다. 목록에 확인 요청(폴링)을 넣지 않는다.
- **저장소 전체 장애:** 저장소에 올리지 못하는 오류(접속 실패, 인증 오류)는 이미지 하나의 실패로 세지 않고, 요약 작업처럼 작업을 잠시 쉰다. 이미지 자체 문제(형식, 크기, 원본 404)만 실패 횟수에 넣는다.
- **켜고 끄기:** 미리 읽기와 축소본 작업은 각각 설정으로 켜고 끈다. 기본값은 수집(`crawl.enabled`)과 같은 방식으로 둔다.
- **같은 글 안의 중복 이미지 주소:** 갤러리처럼 한 번만 만든다.
- **이미 경계보다 아래까지 확보한 게시판:** 다음 확보 때 바로 끝(`exhausted`)으로 둔다. 경계보다 오래된 틀 글은 목록 조건에서 빠지므로 지우지 않아도 된다.
- **조회순 목록:** 최근순과 같이 경계 조건을 건다.
- **DB에는 객체 이름만:** 완료 상태에는 공개 주소가 아니라 객체 이름을 저장하고, 공개 주소는 응답할 때 설정의 공개 주소 앞부분을 붙여 만든다. 저장소나 도메인이 바뀌어도 DB를 고치지 않아도 된다. 로컬 DB를 배포 DB로 옮기는데 버킷을 이미 비웠다면, 축소본 상태를 "아직 없음"으로 되돌리는 SQL 한 줄을 README에 적는다. 그러면 작업이 다시 만든다.

## 4. 테스트

- 자동 테스트는 실제 네트워크를 쓰지 않는다.
  - 이미지 받기: 가짜 응답(작은 PNG/JPEG/GIF를 테스트 안에서 만들어 돌려줌).
  - 저장소: 메모리 가짜 구현. 필요하면 Testcontainers MinIO로 S3 구현 통합 테스트를 하나 둔다(외부 네트워크 없음).
  - geekhack HTML은 지금처럼 직접 쓴 흉내 HTML.
- 확인할 것: 640px 축소·대표 이미지 1280px 추가·비율 유지·작은 원본은 키우지 않음, WebP 인코딩, 움직이는 GIF 첫 장면, 크기 상한 초과·잘못된 이미지 → 실패와 재시도 멈춤, geekhack 첨부는 요청 간격을 거침, 미리 읽기는 빈 간격만 씀, 경계 글 번호 이전 글이 수집·확보·목록·하단 목록에서 빠짐, 과거 글 확보가 경계에서 끝남, 카드·상세 응답의 축소본 주소.
- 프론트: 축소본 있으면 축소본, 없으면 원본 주소를 고르는 함수 테스트. 실제 화면 확인은 로컬에서 R2 버킷에 연결해 한다(자동 테스트는 R2를 부르지 않는다).

## 5. 구현에 맡기는 것

- WebP 라이브러리 선택(맥·리눅스 동작 확인), 인코딩 품질 값.
- 상태를 어디에 둘지(`post_image`에 칸 추가 등)와 마이그레이션 번호(지금 V6까지 있음).
- 작업 실행 간격, 재시도 횟수, 크기·시간 상한의 정확한 값.
- 저장소 클라이언트 라이브러리(AWS SDK v2 S3 등).
- 오래된 글을 숨김으로 처리할지 조회 조건으로 뺄지.
- 응답 필드 이름.

## 6. 남은 위험

- **이미지 권리:** 남의 이미지를 줄여 보관하게 된다. 기존 설계에서 배포 단계에 다시 보기로 한 문제이고, 사용자가 C안을 정했다. 출처(원문 링크)는 계속 보여준다.
- **R2 도메인:** 배포에서 공개 주소를 쓰려면 Cloudflare에 연결한 도메인이 필요하고, R2를 켤 때 결제 수단 등록이 필요할 수 있다. 배포 세팅 때 확인한다.
