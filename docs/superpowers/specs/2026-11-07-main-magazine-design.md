# 메인 매거진(C안) 적용 설계

작성 2026-11-07. 시안: `docs/design/main-c-responsive.html`(사용자 승인), 비교안: `docs/design/main-magazine-options.html`.

## 1. 왜 하는가

- 지금 메인은 짧은 소개와 IC·공동구매 최근 글 두 칸 목록이라, 사진이 작고 지금 무엇이 화제인지 한눈에 보이지 않는다.
- 사용자는 "메인에 하이라이트가 있고, 아래로 스크롤하면 목록이 보이는 매거진 느낌"을 원했고, 세 안 중 C안(벤토 갤러리)을 골랐다. 사진이 주인공인 화면이라 이미지 축소본(R2) 작업과 함께 간다.
- 디스코드 국내 판매 공지는 이번 MVP에서 빼기로 했다(사용자 결정). 메인은 IC·공동구매만으로 만들고, 국내 판매가 들어올 때 다시 디자인한다.

## 2. 목표와 비목표

**목표**
- 메인을 C안대로 바꾼다: 날짜 줄 → 하이라이트(벤토 6칸) → IC 가로 줄 → 공동구매 가로 줄. 데스크톱·태블릿·모바일 세 폭 모두 시안처럼 보인다.
- 하이라이트 6칸은 정해진 규칙으로 자동으로 고른다(사람이 고르지 않는다).
- 공동구매 기간(시작일·마감일)을 요약할 때 AI가 함께 뽑아, 하이라이트의 마감 띠와 공동구매 카드의 D-day에 쓴다(사용자 결정).

**비목표**
- 디스코드 국내 판매(메뉴·줄·포스터 카드). 나중에 따로.
- 목록 페이지(/ic, /gb)와 상세 페이지의 디자인 변경.
- 로그인 기능.
- 하이라이트를 사람이 고르거나 고정하는 기능.
- 열어 둔 메인이 저절로 바뀌는 자동 갱신(폴링).

**하면 안 되는 것 (돌아가도 실패로 본다)**
- 마감일이 불확실한데 D-day를 단정해 보여주는 것. 모르면 보여주지 않는다.
- 어디서든 Vercel 이미지 변환을 쓰는 것(축소본이나 원본을 브라우저가 직접 읽는다).
- 메인 첫 화면이 지금보다 눈에 띄게 느려지는 것.
- 화면 문구에 "해외"를 쓰는 것.
- 자동 테스트가 실제 geekhack·Anthropic·R2를 부르는 것.

## 3. 정한 것

### 3.1 공동구매 기간 (사용자 결정: AI가 뽑는다)

- 요약 응답에 `gbStartDate`, `gbEndDate`(각각 `YYYY-MM-DD` 또는 null)를 더한다. GB 게시판 글만 채우고 IC는 늘 null이다.
- 제목·본문에 적힌 날짜만 쓴다. 연도가 없으면 글 작성일을 기준으로 정한다(요약기에 작성일을 함께 넘긴다). 날짜 표기(월/일, 일/월)가 모호하면 기간 길이가 그럴듯한 쪽으로 읽되, 확신이 없으면 null.
- 제목·본문에 공동구매가 취소·연기됐다고 적혀 있으면 마감일은 null. 이미 끝난 공동구매(마감일이 지났거나 "GB ENDED")라도 날짜가 적혀 있으면 날짜는 그대로 둔다(화면이 지난 마감으로 "끝남"을 보여준다).
- 저장: `post.gb_start_date`, `post.gb_end_date`(DATE). 응답 형식이 틀리거나 마감이 시작보다 앞이면 둘 다 버린다(null).
- 가짜 요약기는 기간을 뽑지 않는다(null). 테스트는 DB에 기간을 직접 넣는다.
- 기존 GB 글과 나중에 IC에서 GB로 옮겨진 글: 요약 작업이 "GB 게시판인데 GB로서 기간을 뽑아 본 적이 없는 요약 완료 글"을 요약 대기 글 다음 순서로 다시 요약한다(항상 켜짐). 뽑아 봤는지는 별도 표시(GB로 요약했을 때만 참)로 구분해, 뽑았는데 null인 글을 계속 다시 요약하지 않는다. 지금 GB 글 약 100개, 한 번에 약 $1.1이며 사용자가 2번 안을 고르며 받아들였다(Claude 판단: 기존 글과 옮겨진 글을 같은 조건으로 처리해 따로 켜는 설정을 두지 않는다). 가짜 요약기로 실행할 때는 다시 요약하지 않는다.
- **제목이 바뀐 공동구매 글은 다시 요약한다 (사용자 결정).** 공동구매는 진행 중에 제목이 "EXTENDED to Dec 10", "[CLOSED]", "[CANCELLED]"처럼 바뀌는 일이 잦고, 30분마다 하는 정기 수집이 바뀐 제목을 받아 온다. GB 글의 제목이 바뀌면 요약 작업이 그 글을 다시 요약해 기간을 새로 뽑는다(글당 약 1.1센트). 이때 본문은 처음 읽은 것을 그대로 쓰고(원문을 다시 읽지 않는다), 새 제목을 함께 넘긴다. 다시 요약하기 전까지는 예전 기간을 그대로 보여준다.
- 본문만 바뀐 연장·취소는 반영되지 않는다. 상세의 "가격·일정은 원문에서 확인해 주세요" 안내를 그대로 둔다.

### 3.2 하이라이트 고르기

- 새 API가 메인 하이라이트 6칸과 날짜 줄 숫자를 한 번에 준다.
- 후보: 숨기지 않았고, 수집 기간 경계 이후이고, 본문을 읽었고, 대표 이미지가 있는 글. "최근 N일"은 작성일(postedAt) 기준이다.
- 칸 규칙(시안 메모 그대로). 앞 칸에 들어간 글은 다시 넣지 않는다.
  - 큰 칸: 최근 7일 새 공동구매 중 조회수 1위
  - 세로 칸: 최근 14일 IC 중 조회수 1위
  - 마감 띠: 오늘(한국 시간) 이후 마감인 공동구매 중 마감이 가장 가까운 글. 없으면 최근 14일 공동구매 조회수 2위를 사진 칸으로
  - 작은 칸 1: 최근 14일 IC 중 댓글 1위
  - 작은 칸 2: 최근 14일 IC 중 조회수 2위
  - 작은 칸 3: 최근 30일 공동구매 중 조회수 1위
- 창(7·14·30일) 안에 후보가 없으면 창을 넓혀(30일 → 90일 → 전체) 고른다. 그래도 없으면 그 칸은 비우고 화면은 남은 칸으로 그린다.
- 날짜 줄 숫자: 최근 7일 새 IC 수, 새 공동구매 수, 14일 안에 마감하는 공동구매 수.

### 3.3 화면

- 메인(`/`)을 시안 C안으로 바꾼다. 날짜 줄(한국 시간 날짜, 위 숫자) → HIGHLIGHT 제목과 리드 → 벤토 6칸 → "01 IC" 줄 → "02 공동구매" 줄. 시안의 "시안 메모" 상자와 "폭별 메모"는 넣지 않는다(시안 설명용).
- 가로 줄: 게시판별 최근 글 10개(지금 메인과 같은 수), 오른쪽 "전체 보기"는 /ic, /gb로. 카드에 한국어 요약 첫 줄(두 줄까지). 공동구매 카드는 시안처럼 기간 칩을 보여준다: 기간이 있고 마감 전이면 "10/30 → 11/13" + "D-8", 마감이 지났으면 "7/6 → 7/27 끝남", 기간을 모르면 칩 없음(시안의 날짜 없는 "공동구매 끝남" 칩은 데이터가 없어 넣지 않는다).
- 이미지: 축소본(640)을 먼저, 없으면 원본(지금 RemoteImage 대체 방식 그대로). 큰 칸은 대표 이미지 1280 축소본을 쓴다.
- 폭: 데스크톱 1024px 이상, 태블릿 600~1023px, 모바일 599px 이하(시안 기준). 가로 줄은 터치로 넘기고, 데스크톱은 좌우 화살표로도 넘긴다. 진행 막대는 실제 스크롤 위치를 반영한다.
- 지금 메인의 소개 문단과 BoardColumn 두 칸은 빠진다.

### 3.4 검토 전 Claude가 정한 것

- **헤더:** 사이트 전체 헤더(글자 로고 "키체크", IC·공동구매 메뉴)는 그대로 둔다. 시안의 영문 "keycheck" 로고와 "로그인" 자리 버튼은 넣지 않는다(로그인 기능이 없는데 눌리는 모양을 보여주지 않는다). 모바일 메뉴 모양(IC·공동구매 탭 줄)만 시안을 따른다.
- **하이라이트 데이터는 서버에서 한 번에:** 메인 첫 화면이 여러 번 왕복하지 않게 하이라이트 API 하나로 받는다.

### 3.5 검토 후 Claude가 정한 것

- **"느려지지 않는다"의 기준:** 페이지 틀(헤더)과 가로 줄이 지금보다 늦게 뜨지 않으면 된다. 하이라이트는 요청마다 계산해 Suspense로 감싸고(자리 표시를 먼저 그림), 큰 칸 이미지는 우선 불러오기(priority)를 준다. 하이라이트 캐시(`'use cache'`)는 이번에 넣지 않는다.
- **끝난 공동구매:** 지난 마감은 "끝남"으로 보여주므로, AI는 끝난 공동구매의 날짜도 지우지 않는다(3.1). 취소·연기만 null.
- **IC에서 GB로 옮겨진 글:** 3.1의 다시 요약 조건이 함께 처리한다.

## 4. 테스트

- 백엔드: 칸 규칙(창, 앞 칸 제외, 마감 띠 대체, 창 넓히기, 빈 칸), 후보 조건(숨김·경계·틀 글·이미지 없음 제외), 기간 응답 검증(형식, 시작>마감, IC는 null), 다시 요약 조건(GB로 뽑아 본 적 없는 글, 제목이 바뀐 GB 글, IC 글은 제목이 바뀌어도 다시 요약하지 않음, 가짜 요약기면 하지 않음).
- 프론트: D-day 계산(한국 시간, 지난 마감은 없음), 칸·줄이 비었을 때 그리기.
- 화면 확인: 세 폭을 Playwright로 렌더링해 시안과 비교.

## 5. 구현에 맡기는 것

- API 경로·응답 필드 이름, 쿼리 방식(칸마다 쿼리 또는 후보를 한 번 읽어 서비스에서 고르기).
- 반응형을 미디어 쿼리로 할지 컨테이너 쿼리로 할지.
- 시안 CSS를 컴포넌트로 나누는 방식.

## 6. 남은 위험

- AI가 날짜를 잘못 읽을 수 있다(특히 월/일 표기). 마감 띠는 크게 보이므로 틀리면 눈에 띈다.
- 대표 이미지가 없는 글이 많으면 하이라이트 칸이 덜 찬다.
