# 한국 벤더 표시 설계

작성 2026-11-07.

## 1. 왜 하는가

- 공동구매·IC 글에는 지역별 판매처(벤더) 목록이 있다. 한국 사용자에게는 한국 벤더(Swagkeys, GeonWorks 등)가 있는지가 가장 중요한데, 지금은 요약의 "벤더" 줄에 글로만 섞여 있고 "등"으로 빠지기도 한다.
- 사용자 요청: 한국 벤더가 있는 글은 목록·메인 카드에 배지로 표시하고, 상세의 벤더 영역에서는 한국 벤더를 맨 앞에 굵게, 그 상품의 판매 페이지 링크와 함께 보여준다.

## 2. 목표와 비목표

**목표**
- 목록 페이지(/ic, /gb) 카드, 메인 하이라이트 칸, 메인 가로 줄 카드에 "한국 벤더" 배지(사용자 결정 문구).
- 상세의 벤더 줄: 한국 벤더를 맨 앞에 굵게, 원문에 적힌 그 벤더 판매 페이지로 링크. 다른 벤더는 지금처럼 글자로.
- 원문 첫 글의 링크(글자 + 주소)를 저장하고, 요약할 때 AI가 벤더 목록(이름·지역·판매 링크)을 뽑는다.

**비목표**
- 한국 벤더가 아닌 벤더의 링크, 벤더별 가격·재고, 벤더 필터·정렬.
- 상세 하단 주변 글 목록 줄의 배지(작은 줄이라 이번에는 넣지 않는다 — Claude 판단).
- 이미 수집한 글 전체를 다시 읽고 다시 요약하기(배포하면 처음부터 수집한다 — 사용자 결정. 개발 확인용으로 몇 개만).

**하면 안 되는 것**
- 원문에 없는 주소로 링크하는 것(AI가 지어낸 주소). 링크는 저장한 원문 링크 중 하나여야 한다.
- 한국 벤더가 아닌데 배지를 붙이는 것(애매하면 붙이지 않는다).
- 자동 테스트가 실제 geekhack·Anthropic을 부르는 것. 화면 문구에 "해외".

## 3. 정한 것

### 3.1 원문 링크 저장
- 글 첫 페이지를 읽을 때 첫 글 본문(`div.inner`)의 `a[href]` 중 http/https 주소를 `{text, url}`로 모은다. 같은 주소는 한 번만, 본문 순서, 최대 200개, 글자는 앞뒤 공백 정리 후 200자까지, 주소는 2,000자를 넘으면 버린다. 첨부 이미지 링크(`action=dlattach`)와 geekhack 내부 글 링크는 뺀다(Claude 판단: 벤더 링크가 아니다).
- `post.body_links`(JSONB)에 저장한다. 새 글 저장과 틀 글 채우기가 같이 쓴다. API로는 내보내지 않는다.

### 3.2 AI가 벤더를 뽑는다
- 요약기에 링크 목록을 함께 넘긴다(`<links>` 구역, 한 줄에 `글자 | 주소`, 최대 150개).
- 요약 응답에 `vendors: [{name, region, url}]`.
  - `name`: 벤더 이름(원문 표기).
  - `region`: 지역 코드 하나(KR, US, CA, EU, UK, AU, OCE, CN, SG, SEA, JP, TW, … ) 또는 null. 한 벤더가 여러 지역이면(예: "Swagkeys(KR/CN)") 한국이 있으면 KR.
  - `url`: `<links>`에 있는 주소 중 그 벤더의 판매 페이지로 보이는 것, 없으면 null.
- 본문에 벤더 목록이 없으면 빈 배열. IC도 계획된 벤더가 적혀 있으면 뽑는다.
- 검증: `url`이 넘긴 링크에 없으면 null로 바꾼다. 이름이 비면 그 항목을 버린다. 최대 30개.
- 가짜 요약기는 빈 배열. `post.vendors`(JSONB)에 저장한다.
- AI의 스펙표 "벤더" 줄은 그대로 두되, 화면이 구조화된 벤더 목록이 있으면 그 줄을 숨기고 벤더 줄을 새로 그린다.

### 3.3 API
- 카드(`PostCardResponse`): `hasKoreanVendor`(boolean, region이 KR인 벤더가 있으면 true).
- 상세(`PostDetailResponse`): `vendors: [{name, region, url}]`, 한국 벤더를 앞으로(그 안의 순서와 나머지 순서는 원문 그대로).

### 3.4 화면
- 배지 문구 "한국 벤더"(사용자 결정). 목록 카드(PostCard)는 기존 게시판 배지 옆, 메인 하이라이트 칸은 배지 줄, 메인 가로 줄 카드는 사진 위 칩 줄에 둔다. 강조색 계열로 눈에 띄게, 기존 배지 크기와 맞춘다.
- 상세: 벤더 목록이 있으면 스펙표에 "벤더" 줄을 새로 그린다(기존 AI "벤더" 줄이 있던 자리, 없으면 끝에). 한국 벤더는 굵게, url이 있으면 새 탭 링크(`rel="noopener noreferrer"`). 나머지는 "이름(지역)"을 쉼표로 잇는다. AI 스펙표에서 라벨에 "벤더"가 들어간 줄은 숨긴다.

### 3.5 개발 데이터
- 기존 글은 다시 읽지 않는다. 확인용으로 한국 벤더가 있는 공동구매 글 몇 개만(예: SWG Nightshift, GMK CYL Blanks, DCS SMRT R2) 틀 글로 되돌려(이미지·본문 지우고) 다시 읽고 요약한다(Claude 약 몇 센트).
- 되돌릴 때 `detail_fetched_at`·본문·이미지와 함께 `summary_status = 'PENDING'`으로 바꾸고 `body_links`·`vendors`는 NULL로 둔다. 틀 글 채우기(`fillSkeleton`)는 요약 상태를 바꾸지 않아서, DONE으로 남기면 다시 요약하지 않고 벤더도 뽑지 않는다.

## 4. 테스트
- 파서: 첫 글의 링크 수집(중복, 상한, 첨부·내부 링크 제외, http/https만).
- 요약기: `<links>` 전달, vendors 매핑, 없는 url → null, 이름 빈 항목 제거, IC/GB 모두, 스키마.
- API: hasKoreanVendor, 상세 vendors 정렬.
- 프론트: 벤더 줄 만들기(한국 앞으로, 링크 유무), 배지 표시 조건(순수 함수).

## 5. 구현에 맡기는 것
- 칼럼·필드·함수 이름, 지역 코드 목록의 정확한 범위, 배지 색.

## 6. 남은 위험
- AI가 지역을 잘못 읽을 수 있다(예: 한국 사람이 운영하는 다른 나라 상점). 원문 표기("KR", "Korea", "한국")를 근거로만 정하게 한다.
